# Berserk VPN Bot (berserkv5)

بات فروش و مدیریت اشتراک VPN روی تلگرام — پرداخت کارت‌به‌کارت، کیف پول داخلی،
سیستم نمایندگی، تحویل خودکار از طریق پنل (PasarGuard/YouPanel) یا استخر لینک
دستی، و پنل مدیریت کامل داخل خود تلگرام.

> یادداشت‌های نسخه‌به‌نسخه‌ی قدیمی (v5.x تا v6.5.1) در `PATCH_NOTES.md` و
> `VERSION.txt` نگه داشته شده‌اند. این فایل فقط وضعیت *فعلیِ* پروژه را
> توضیح می‌دهد.

---

## امکانات کلیدی

**فروش و پرداخت**
- کیف پول داخلی + تأیید رسید کارت‌به‌کارت
- ۴ حالت خرید در سطح پلن: مستقیم، انتخاب تعداد، عمده‌فروشی، غیرفعال
- سیستم نمایندگی سه‌سطحی (همکار / نماینده / عمده‌فروش) با تخفیف پلکانی
- کد تخفیف، رفرال با پاداش، ضدتقلب (بلاک رفرال خودی، تشخیص رسید تکراری)

**تحویل سرویس**
- **استخر لینک (pool):** لینک‌های آماده از قبل وارد می‌شوند، بات فقط تخصیص می‌دهد
- **تأمین‌کننده (provider):** اتصال زنده به پنل و ساخت خودکار کاربر لحظه‌ی خرید
  - آداپتور **PasarGuard** — از چند پنل هم‌زمان پشتیبانی می‌کند (پنل اصلی +
    نودهای بعدی)، هرکدام به‌صورت گزینه‌ی جدا در ویزارد ساخت پلن
  - آداپتور **YouPanel** (تأمین‌کننده‌ی قدیمی، هنوز پشتیبانی می‌شود)
  - پشتیبانی از **پلن نامحدود** (حجم یا مدت بدون سقف) در کنار پلن‌های حجمی
- اکانت تست رایگان با محدودیت تعداد دستگاه

**مدیریت (پنل ادمین داخل تلگرام)**
- ساخت/ویرایش/کپی دسته و پلن با ویزارد مرحله‌ای
- عضویت اجباری کانال (روشن/خاموش و تنظیم کانال از همان پنل تنظیمات)
- گزارش‌ها و بخش‌بندی کاربران (خریدار/غیرفعال/نزدیک‌به‌انقضا/...)
- ویرایش متن‌ها با inheritance پلن ← دسته ← عمومی
- بکاپ و ری‌استور دیتابیس بات + **بکاپ خودکار پنل PasarGuard** (DB + کانفیگ) به تلگرام

## نصب سریع

### گزینه ۱: Railway

1. ریپازیتوری را به Railway وصل کن (Nixpacks خودکار تشخیص داده می‌شود، `railway.json` از قبل تنظیم شده).
2. یک Volume بساز و `DB_PATH` را داخل آن قرار بده (مثلاً `/data/berserk.db`) — وگرنه با هر ری‌دیپلوی دیتابیس پاک می‌شود.
3. متغیرهای محیطی زیر (بخش «مرجع متغیرها») را در تنظیمات سرویس Railway وارد کن.
4. Deploy بزن. لاگ‌ها را از تب Deployments Railway می‌بینی.

### گزینه ۲: سرور خودت (Ubuntu 22.04/24.04) — نصب تعاملی

```bash
git clone https://github.com/iliyamakilva/berserkv5.git
cd berserkv5
sudo bash deploy/install-server.sh
```

اسکریپت به‌صورت تعاملی توکن بات، آیدی ادمین، و (در صورت تمایل) اطلاعات پنل
PasarGuard را می‌پرسد، بعد خودش Python 3.11، virtualenv، وابستگی‌ها، و یک
سرویس systemd (`berserk-bot.service`) با ری‌استارت خودکار می‌سازد. اجرای
دوباره‌ی اسکریپت امن است (idempotent) — اگر `.env` از قبل باشد می‌پرسد که
نگهش دارد یا از اول بسازد.

دستورهای روزمره بعد از نصب:
```bash
sudo systemctl status berserk-bot     # وضعیت
journalctl -u berserk-bot -f          # لاگ زنده
sudo systemctl restart berserk-bot    # بعد از هر تغییر کد یا .env
nano .env                             # ویرایش تنظیمات
```

## مرجع متغیرهای محیطی

نمونه‌ی کامل با توضیح فارسی هر خط در **`.env.example`** موجود است. مهم‌ترین‌ها:

| متغیر | الزامی؟ | توضیح |
|---|---|---|
| `BOT_TOKEN` | ✅ | توکن از @BotFather |
| `ADMIN_ID` | ✅ | یک یا چند آیدی عددی، با کاما جدا |
| `ADMIN_COMMAND` | خیر | دستور مخفی پنل ادمین به‌جای `/admin` |
| `DB_PATH` | خیر (پیش‌فرض `berserk.db`) | مسیر فایل SQLite؛ روی Railway حتماً داخل Volume |
| `PASARGUARD_PANELS_JSON` | خیر | آرایه‌ی JSON یک یا چند پنل PasarGuard؛ فرمت کامل در `.env.example` |
| `YOUPANEL_*` | خیر | تنظیمات تأمین‌کننده‌ی قدیمی YouPanel |
| `TRIAL_*` | خیر | تنظیمات اکانت تست رایگان |
| `PASARGUARD_BACKUP_*` | خیر | بکاپ خودکار پنل PasarGuard (پایین‌تر توضیح داده شده) |
| `BACKUP_INTERVAL_SECONDS` / `BACKUP_RETENTION_COUNT` | خیر | بکاپ خودکار دیتابیسِ خودِ بات (فرق دارد با بکاپ پنل) |

## اتصال تأمین‌کننده (Provider)

هر پلن یک `provider_key` دارد: `pool` (لینک دستی) یا کلید یکی از پنل‌های
تعریف‌شده در `PASARGUARD_PANELS_JSON` یا `youpanel`. اضافه‌کردن یک پنل جدید
فقط یعنی یک آیتم به آرایه‌ی JSON اضافه کنی — نیازی به تغییر کد نیست؛ خودش
در ویزارد ساخت پلن به‌عنوان گزینه‌ی جدید ظاهر می‌شود.

```json
[
  {
    "key": "pasarguard_main",
    "label": "پنل اصلی",
    "base_url": "https://panel.example.com",
    "username": "admin",
    "password": "SECRET",
    "group_ids": [1],
    "verify_ssl": true,
    "timeout": 20
  }
]
```

`group_ids` را از خودِ پنل، بخش **Groups** بردار (پاسارگارد از نسخه‌ی v3
به بعد دیگر بر اساس اسم inbound کار نمی‌کند؛ کاربر به یک یا چند Group وصل
می‌شود و خودِ Group تعیین می‌کند کدام inbound فعال باشد — پس دیگر نیازی
نیست اسم inbound را جایی تایپ کنی).

**پلن نامحدود:** در ویزارد ساخت پلن، مرحله‌ی حجم یک دکمه‌ی «♾ حجم نامحدود»
دارد؛ برای پلن‌های موجود هم کافیست روی فیلد «حجم» کلمه‌ی «نامحدود» را
بفرستی. مقدار `0` به‌صورت conventionally به معنای بدون‌سقف به پنل ارسال
می‌شود (نه اینکه پلن تنظیم‌نشده باشد).

## عضویت اجباری کانال

از پنل ادمین → ⚙️ تنظیمات:
- «کانال عضویت اجباری» را با `@username` یا آیدی عددی پر کن
- روشن/خاموشش کن با دکمه‌ی وضعیت

اگر کانال اشتباه تنظیم شود یا بات ادمین کانال نباشد، این قابلیت به‌جای
قفل‌کردن کل ربات fail-open می‌کند (کاربر رد می‌شود، فقط در لاگ هشدار ثبت
می‌شود).

## بکاپ‌ها

دو سیستم بکاپ کاملاً جدا وجود دارد، هر دو زیر «💾 بک‌آپ و ری‌استور»:

1. **بکاپ دیتابیس خود بات** — خودکار هر `BACKUP_INTERVAL_SECONDS`، یا دستی از پنل. مخصوص کاربران/کیف‌پول/سفارش‌های *بات*.
2. **بکاپ پنل PasarGuard** — دیتابیس و فایل‌های کانفیگ *پنل* (نه بات). نیاز به تنظیم `PASARGUARD_BACKUP_COMMAND` در `.env` دارد (دستور دقیق دامپ+تار را خودت متناسب با نام کانتینر/مسیر compose واقعی‌ات می‌نویسی — نمونه در `.env.example`). دو حالت:
   - `PASARGUARD_BACKUP_MODE=local` — وقتی بات و پنل روی یک سرورند (وضعیت فعلی)
   - `PASARGUARD_BACKUP_MODE=ssh` — وقتی پنل روی سرور جداگانه است (نیاز به `pip install asyncssh`)

   بعد از تنظیم، `PASARGUARD_BACKUP_ENABLED=true` کن تا هم دکمه‌ی دستی «بکاپ پاسارگارد (همین الان)» کار کند و هم چرخه‌ی خودکار روزانه فعال شود.

## معماری کاتالوگ (خلاصه)

`دسته (Category) → پلن (Plan)`. هر پلن یک `purchase_mode` (نحوه‌ی خرید) و
یک `provider_key` (نحوه‌ی تحویل) دارد. توضیح دسته در صفحه‌ی لیست پلن‌ها
نمایش داده می‌شود (قبل از انتخاب پلن)، توضیح خودِ پلن در صفحه‌ی تأیید خرید
نهایی — این دو فیلد جدا هستند، اگر توضیح یک دسته قدیمی/اشتباه به‌نظر می‌رسد
احتمالاً باید توضیح همان **دسته** را ویرایش کنی نه پلن را.

جزئیات کامل‌تر (چیدمان دکمه‌ها، مدیریت کاربران، سیستم محتوا) در فایل‌های:
`CONTENT_ADMIN_GUIDE.txt`, `ADMIN_USERS_REPORTS_GUIDE.txt`, `CUSTOMER_USAGE.txt`

## توسعه و ساختار پروژه

| فایل | مسئولیت |
|---|---|
| `bot.py` | ورودی اصلی، منوی کاربر، ثبت همه‌ی ماژول‌ها |
| `admin.py` | کل پنل مدیریت (بزرگ‌ترین فایل پروژه) |
| `db.py` | لایه‌ی دیتابیس (SQLite)، مهاجرت‌های ستون خودکار |
| `subs.py` | آداپتورهای Provider (`PasarGuardProvider`, `YouPanelProvider`) و استخر لینک |
| `commerce.py` | منطق خرید/تحویل |
| `force_join.py` | میان‌افزار عضویت اجباری کانال |
| `pasarguard_backup.py` | بکاپ خودکار پنل PasarGuard |
| `backup.py` | بکاپ/ری‌استور دیتابیس خودِ بات |
| `settings.py` | تنظیمات runtime (SQLite)، جدا از `config.py` (env-only) |
| `deploy/` | اسکریپت نصب سرور + یونیت systemd |

برای افزودن یک تأمین‌کننده‌ی جدید غیر از PasarGuard/YouPanel، یک کلاس تازه
از `ProviderAdapter` در `subs.py` بساز و در `_PROVIDER_REGISTRY` ثبتش کن —
بقیه‌ی سیستم (ویزارد پلن، تحویل، بکاپ) بدون تغییر کار می‌کند.
